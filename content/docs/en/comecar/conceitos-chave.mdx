# Key concepts

Three words come up again and again in this documentation. Understanding each one well saves you time down the road.

<Callout type="tip" title="How to read this page">
  No need to memorize anything — just know what each term means. When you see
  "page" or "DataID" elsewhere in the docs, come back here as a quick reference.
</Callout>

## 1. Project

The highest-level unit of work. A **project** represents **one game**.

Everything you write lives inside a project. You can have as many projects as you want on your account — one per game, one per experiment, one per client.

## 2. Page

A **page** is a subject in your game. E.g.: "Iron Sword", "Shadow Mage", "Main Economy", "Core Loop".

Pages are organized in a tree — every page can have sub-pages. Typically a GDD has five top-level groups (Overview, Design, Content, Presentation, Production) and dozens or hundreds of children below them.

Every page has a title, a description written in blocks (paragraphs, lists, tables, images, callouts) and the domain tags that say what it's about.

<Callout type="tip" title="Cross-references">
  Writing <code>$[Page Name]</code> inside your text creates a clickable link to
  another page. That's what turns the document into a navigable web instead of a
  pile of loose files.
</Callout>

## 3. DataID

A **DataID** is a stable, readable nickname for a page — `DATA_FIRE_BALL`, `DATA_GOLD`, `DATA_ENEMY_GOBLIN`.

### Why it matters

The app generates an internal identifier (`a8f3e9d2-7c1b-…`) for every page, but it's unreadable and it changes when you duplicate or import a project. The DataID is the name **you** choose, and it doesn't change when the page is renamed or moved somewhere else.

It's mostly there so things can be matched up: when someone (or Claude, through the integration) needs to point at a specific page, the DataID is the address you can rely on.

### How to set one

1. Open any page
2. **Right below the title** there's a discreet field:
   - When empty: **"+ DataID"** shows up in grey
   - When set: **"ID: DATA_…"** shows up as a clickable pill
3. Click the field
4. The app **suggests one automatically** based on the title — e.g. "Iron Sword" → `DATA_IRON_SWORD`
5. Accept or edit it (worth keeping a convention across the project)
6. The app warns you if another page already uses that DataID

### When to use it

You don't need one on every page. It pays off on the pages you reference a lot, the ones the AI integration will need to find, and the ones that stand for concrete game entities (an item, an enemy, a currency).

<Callout type="tip" title="Naming convention">
  Prefix <code>DATA_</code> + kind + identifier, in UPPER_SNAKE.
  Examples: <code>DATA_GOLD</code>, <code>DATA_FIRE_BALL</code>,
  <code>DATA_ENEMY_GOBLIN</code>. Helps you glance at one and know what it is.
</Callout>
